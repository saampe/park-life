# Park Life Implementation Plan
> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.
**Goal:** Deliver the approved park as an animated, private browser app with playable signal controls.
**Architecture:** Buildless HTML/CSS/ES modules; raster artwork composited in a Canvas scene; pure simulation engine separated from renderer and accessible DOM controls. Persist device-local world separately from temporary simulator state.
**Tech Stack:** Browser Canvas 2D, JavaScript ES modules, node:test, Python static development server.
**Spec:** docs/superpowers/specs/2026-11-06-park-life-design.md
## Global Constraints
- Use the exact approved artwork and shark design.
- Gmail: one package per five new emails, carrying the remainder; calendar: busy at four hours.
- Europe/Stockholm time and seasons. No names, messages, event titles or source credentials in app.
- No absence penalties. No real integrations until the user has tried the app.
## Review Focus
- Negative, repeated, fractional counts must not duplicate parcels.
- Returning after a long absence must not block the UI or guarantee a reward.
- Missing/corrupt browser storage must not prevent play.
- Stockholm DST and dates near local midnight must yield correct day/season.
- Small portrait screens must retain accessible controls and full shark visibility.
